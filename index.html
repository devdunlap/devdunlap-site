LOG-002ObservabilityMigration SEV · LESSON

The migration where you can't parse live: Splunk → Datadog

Splunk extracts fields when you search — invent a field mid-query, on data ingested months ago. Datadog parses once, at intake: fix a Grok pipeline today and it only fixes tomorrow's logs. That single difference is where migrations hurt, and it's why the pipeline has to be designed before the first log moves, not after.

Outcome → Grok-parser pipelines built per log source, so queries, dashboards, and monitors worked on day one of the cutover — not day thirty.

Why ClickOps is a real service

Plenty of growing businesses run their cloud from the console — clicking through AWS screens to ship real work. The industry sneers at "ClickOps," but the honest problem was never the clicking. It's clicking without discipline: no record of what changed, no guardrails, no way to repeat it, and one wrong click away from an outage.

I do ClickOps the way an SRE does everything: changes planned and logged, dangerous actions fenced off, steps documented so they can be repeated — and automated later, when the volume justifies it. You get enterprise operational discipline at the scale your business actually is today, with a clear path to full infrastructure-as-code when you're ready.

LOG-001Deployment SafetyGuardrailsSEV · PREVENTED

The switch that wasn't supposed to happen

A team was told — in writing, in the repo — never to flip a blue-green deployment while live traffic was still pointed at it, because it would break production. They flipped it anyway, with traffic running. Instructions don't stop incidents; systems do.

Outcome → a Python guardrail that blocks the traffic switch while live traffic is present — while still letting engineers run blue and green deployments with full autonomy. The safe path became the only path.

LOG-002ObservabilityMigrationSEV · LESSON

You can't parse live in Datadog like you can in Splunk

Splunk is schema-on-read: fields are extracted when the search runs, so a parser fix is retroactive across months of data. Datadog is schema-on-write: Grok pipelines parse at intake, and a pipeline change only affects new logs. Teams discover this mid-migration, when their dashboards come up empty.

Outcome → pipelines designed and validated per log source before cutover — the unglamorous work that decides whether a migration is a project or a postmortem.

LOG-003ComplianceAlertingSEV · PROOF

Proving compliance by alerting on nothing

A European regulation required a team to know immediately if a certain condition ever occurred. So the alert was inverted: it watches for the value being NULL — the absence of the condition — so silence isn't ambiguity, it's evidence.

Outcome → continuous, provable compliance: at any moment, the team could show the condition had never occurred, instead of arguing that it probably hadn't.

LOG-004DebuggingDistributed SystemsSEV · TECHNIQUE

One ID, end to end: debugging with trace & correlation IDs

An error surfaces in one service; the cause lives three services away. Without a shared ID, you're reading tea leaves across log files. With a correlation ID propagated through every hop, one search reconstructs the whole request — and when an async hop drops the ID, the trail goes cold exactly where the bug lives, which is its own clue.

Outcome → this is why the Log Parser CLI treats trace IDs as first-class data — the debugging technique and the tool are the same idea.

LOG-005AWSECRSEV · OPERATIONS

Rotating ECR repositories

Container registries quietly become critical infrastructure: images pile up, pipelines pin to them, and a careless rotation breaks every deploy downstream. Rotating repositories safely means inventorying what depends on each one before anything moves.

Outcome → rotation done as an operation, not an adventure — dependencies mapped first, cutover verified per consumer.
